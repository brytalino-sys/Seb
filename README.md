# Себес

Калькулятор себестоимости, заказов и отказов для домашних кондитеров.

Прототип 0.1. Без сборки, без сервера, без зависимостей: три скрипта и один CSS.
Данные хранятся в браузере пользователя (`localStorage`).

## Что уже работает

- Справочник ингредиентов с ценой за упаковку и датой цены
- Расчёт себестоимости: ингредиенты + работа + накладные
- Базовый выход рецепта (кг, г, шт, порции) и пересчёт заказа на любой объём
- Декор как отключаемая часть рецепта: тумблер в окне заказа
- Общая ставка за час или раздельные ставки по этапам, переключаются тумблером
- Рекомендуемая цена от целевой маржи, пересчёт на лету
- Заказы со статусами, временем выдачи, доставкой или самовывозом и адресом
- Календарь заказов по датам выдачи с загрузкой по дням
- Архив выполненных заказов: из рабочего списка уходят, в аналитике остаются
- Оценки и отзывы клиентов у выданных заказов
- Журнал отказов: сумма, канал, этап срыва, причина
- Аналитика из трёх разделов:
  - Деньги: выручка, продукты, труд, накладные, прибыль и маржа по месяцам, график
  - Отказы: конверсия, упущенная выручка, доли причин, пересечение причина-канал, динамика
  - Отзывы: средняя оценка, распределение, оценки по рецептам, повторные клиенты
- Светлая и тёмная тема, пустые состояния, выгрузка и восстановление копии
- Работает и как обычный сайт, и как Telegram Mini App. SDK Telegram загружается
  только при запуске изнутри Telegram и не блокирует страницу, если telegram.org недоступен

## Запуск локально

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Открывать именно через сервер, а не двойным щелчком по `index.html`:
`localStorage` и относительные пути на `file://` работают непредсказуемо.

## Публикация на GitHub Pages

1. Создать репозиторий, загрузить все файлы в корень.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Через минуту сайт будет на `https://<логин>.github.io/<репозиторий>/`.

Файл `.nojekyll` уже лежит в корне — без него Pages игнорирует часть файлов.

## Структура

| Файл | Назначение |
|---|---|
| `calc.js` | Все формулы. Чистые функции, ничего не рисует и не хранит |
| `store.js` | Хранение и демо-данные. Остальной код не трогает `localStorage` напрямую |
| `app.js` | Экраны и навигация. Деньги не считает, берёт из `calc.js` |
| `styles.css` | Токены и компоненты, обе темы |
| `index.html` | Каркас, таббар, шторка |
| `build-artifact.js` | Сборка однофайловой версии |

## Формулы

```
множитель      = нужный объём / базовый выход рецепта
ингредиенты    = Σ (цена за базовую единицу × количество) × множитель
работа         = Σ (минуты / 60 × ставка этапа) × множитель
база           = ингредиенты + работа
себестоимость  = база × (1 + накладные% / 100)
цена           = себестоимость / (1 − маржа% / 100)
прибыль        = цена − себестоимость
```

Позиции с признаком «не растёт с весом» (`fixed`) не умножаются на множитель:
коробка, топпер, надпись стоят одинаково на любой вес. Ставка этапа берётся своя, если включены раздельные ставки,
иначе общая. Работа не умножается на множитель, если выключен тумблер
«Работа растёт вместе с объёмом».

Количество приводится к базовой единице (г, мл, шт), цена ингредиента —
к цене за базовую единицу. Килограммы и литры умножаются на 1000.

## Как считаются расходы

Отдельного учёта закупок нет. Расходы берутся из себестоимости выполненных
заказов и разбиваются на три части, потому что это разные по природе деньги:

- **Продукты** — настоящие траты
- **Труд** — доход самой кондитерши, из кармана не уходит
- **Накладные** — расчётная величина, а не чеки

Поэтому рядом с прибылью показывается «деньги за вычетом продуктов»: это
ближе всего к тому, сколько реально прибавилось. Доставка считается по способу выдачи, см. версию 0.5.2.

## Цвета графиков

Палитра проверена на различимость при дальтонизме скриптом из набора dataviz
(светлая и тёмная тема отдельно). Менять значения `--c-ing`, `--c-lab`,
`--c-ovh`, `--c-prof` без повторной проверки не стоит.

## Версия 0.4

- Налог самозанятого (НПД 4%, 6% для компаний) в цене и в дашборде, переключается в настройках
- Выход рецепта — вес готового изделия, упёк считается от массы продуктов
- Цены продуктов показываются за кг, л или шт; смена единицы у используемого продукта запрещена
- Сумма заказа следует за весом, декором, налогом и доставкой; «Итого клиенту» и «Тебе на руки»
- «Не состоялся» из карточки заказа переносит его в аналитику отказов
- Себестоимость выданного заказа фиксируется в день выдачи
- Импорт копии проверяется и очищается; нечитаемые данные не затираются; ошибка сохранения видна
- Даты по местному времени

## Версия 0.5

- Главная: деньги месяца (пришло, закупки, налог, осталось), ближайшие заказы, вход в календарь
- Закупки: сумма чека, что купили, дата; отдельный список по месяцам
- Вкладки «Продукты» больше нет: продукты добавляются и меняют цену прямо из рецепта, справочник открывается со списка рецептов
- Вместо «декора» флаг «не растёт с весом» у продукта и этапа работы; тумблер декора в заказе убран
- Нейтральные обращения без рода; старые причины отказов переведены автоматически
- Защита данных: просьба к браузеру не стирать данные, автокопии раз в день (последние 5),
  напоминание о копии раз в неделю, отправка файла копии себе, восстановление из файла
- Вкладки видны и внутри Telegram

## Версия 0.5.1 – проверка калькулятора

- Коробка и другие позиции «не растёт с весом» не входят в массу закладки и не просят «массу 1 шт»
- Себестоимость выданного заказа больше не пересчитывается по новым ценам при добавлении отзыва,
  смене плательщика или после удаления рецепта
- В окне заказа налог считается со всей суммы вместе с доставкой, как в аналитике
- Отрицательные количества, минуты и проценты считаются нулём; мелочи форматирования («-0%»)

## Версия 0.5.2 – три способа выдачи

- Самовывоз: доплаты нет
- Везу сам: плата за доставку входит в заработок
- Курьер: клиент платит за доставку, деньги уходят курьеру и в выручку и заработок не входят;
  налог при этом берётся со всей суммы, которую заплатил клиент
- Окно заказа и аналитика считают доставку одинаково

## Версии 0.5.3–0.5.5

- С экрана рецептов убран блок про сорвавшиеся заказы (он есть в аналитике и в заказах)
- Календарь: тап по дню открывает окно дня – чьи заказы и во сколько, сумма, сколько осталось выдать,
  или «заказов нет»; оттуда же можно добавить заказ на этот день
- Точки под числом: по одной на заказ (до трёх, дальше «+N»), выданные бледные
- Заказы: календарь сверху, список под ним на одном экране, без переключателя

## Чего пока нет

- Сервера и общей базы: данные живут только в одном браузере
- Авторизации
- Подписки и приёма платежей
- Истории цен ингредиентов
- Учёта закупок партиями
- Экрана помощи

Проверить на живых кондитерах. Прежде чем писать бэкенд, нужно понять,
пользуются ли журналом отказов — это главная гипотеза продукта.
